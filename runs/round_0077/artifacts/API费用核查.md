# A2 MVP API费用核查

核查日期：2026-10-20。范围：outputs/a2_mvp_v1 的历史运行记录；本次核查不调用模型，不启动实验。

生成/评分以 analysis/memos_generation_attempts.jsonl、memos_judge_attempts.jsonl 的usage合计，不叠加缓存usage。估计取 estimates/memos、estimates/mem0 的当前逐条usage，加去重恢复日志old_usage（907条旧失败记录未返回usage）。建池取 support_audit/last_execution.json 一次。早期未持久化的请求及未返回usage的失败费用未知；不是供应商账单，不能据此精确推算金额。

主实验4062×8=32496次成功生成，外加敏感性实验1200次，共33696次成功生成及33696次评分。生成日志34628条逻辑事件，其中932条失败，记录36574次底层尝试；成功响应33696次。932条失败事件未记录token，不能声称实际账单费用为零，也不能称它们是主要已测支出。memos估计4062条成功；mem0估计4476条中3929成功、547失败，后者未返回token。mem0尚未进入B1/A2生成与评分。

## 为什么贵

1. 从400条试验扩展到4062条八臂全量；每个回答还要再调用评分器。主矩阵仅生成和评分就64992次成功调用，敏感性再加2400次。
2. 每个实验臂重复发送问题和记忆上下文，生成输入3916万token，是最大token来源。
3. Stage1不是输出一个分数，而是为每条记忆输出六类概率、条件和实体字段。两个系统的结构化输出共988万token，且mem0仅估计就1141万token，没有最终跨系统评分结果。
4. 有建池审查、敏感性测试等额外开销。Smoke/400/full有缓存复用，不能把三个完整矩阵重复相加；lambda=1复用主结果。
5. 当前生成缓存键含arm、lambda及控制器配置，因此即便最终prompt相同，也不能跨不同arm/config自动复用生成。可能增加重复输入费用，但本次未量化实际同prompt请求数量，不宣称全部可省。

## 执行控制不足

任务书要求全量矩阵，但每阶段30000调用上限不是全流程token或金额上限。未把全量矩阵转换成累计费用预估，也没有累计token/金额止损。并发12加快余额消耗，不会让单次请求本身收费乘12。批次前和生成前的账户检查未能在估计批次内及时停掉后续不可用请求。重试次数不应当作收费倍数；8192是估计输出上限，不是每次自动收费8192。

本次只诊断，没有修改机制、重试逻辑、预算或实验。没有读取或上传密钥/账单。要解释精确人民币金额，需对齐实际供应商账单、历史模型价格、缓存命中优惠及账期。记录中的估计输入缓存命中很少：memos 0/7477885，mem0 23549/5597354；生成/评分顶层usage丢弃缓存细分，不能推定它们命中率也为零。
