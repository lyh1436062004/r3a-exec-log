## 三、统一转化怎么改善:error-driven,别凭感觉加规则

改善方法不是想新规则,是**让蕴含审计通过的那个子集告诉你渲染丢了什么**。对"事实在记忆里、UA3 却没让模型用上"的样本做失败分类,常见四类,对应四个修法:

1.  **字段级丢失**:`memory_text` 是 first-key-wins 级联,取了 `memory_value` 就丢了 `memory_key` 的主题上下文和 metadata 里的时间/来源。修法:定义 canonical **EvidenceRecord** schema——`{id, text, event_time?, ingest_time?, source/session?, entity_anchors?}`,渲染时可用字段全部呈现,而不是挑一个字段。
2.  **多事实记忆**:关键事实埋在长记忆中段。修法:渲染层做原子化拆分或段内标记(拆分不改内容,不违反冻结)。

4.  **pref\_note / preference 类的渲染形式**是否可用(现在是裸文本追加)。

## 四、时间戳缺失怎么处理

先做一个区分,然后给三级回退和适配器设计:

**事件时间 vs 写入时间。** HaluMem 的 `chat_time` 是事件时间;baseline 记录里 `search_meta.has_ts: true` 说明 memos 返回的对象里**某处有时间字段**(`memory_timestamp` 级联找 created\_at/updated\_at/metadata)——先确认那是写入时间还是事件时间。如果只是写入时间,对"某时间点前/后"的问题它是弱代理(HaluMem 按会话顺序写入,写入序 ≈ 事件序的近似),弱代理也比没有强,但要带不确定度使用。

**冻结原则的精确边界**:冻结的是"检索返回的集合"——不重新检索、不查库、不添加记忆。但**挖掘返回对象内部的一切信息是解析,不是检索**,完全合法:深层 metadata、记忆文本里的日期表达、时态、"去年/后来/搬去了"这类状态变化词,都可以提取成带不确定度的时间区间。

**三级回退**(之前讨论过,现在落到 EvidenceRecord 上):① 对象内时间字段;② 文本内时间线索解析;③ 都没有 → 时间后验平坦 → **决策自动降级**:SELECT 不可用,转 QUALIFY——"记忆未标注时间,无法确认先后,基于内容本身……"或呈现双状态。卖点还是那句:元数据缺失是后验不确定性升高的正常情形,动作随之保守化,不是 if-else 异常分支。

**适配很多智能体 = adapter + capability mask**:每个记忆系统写一个薄适配器填 EvidenceRecord 的可用字段;controller 的行为是可用字段掩码的函数。论文里做一张表(memos:无事件时间;mem0:有时间戳;……),再测性能随掩码的退化曲线——跨系统泛化实验就这么组织,缺字段从负担变成实验轴。

**外加一个便宜的诊断臂**:HaluMem 源事件有真实时间,你有 gold 对齐——给 gold 记忆附上真实事件时间,只重跑时间类问题子集,量化"memos 不返回事件时间的代价 = Xpp"。这是一个 actionable 的系统设计发现("记忆系统应当透传事件时间元数据"),审稿人喜欢这种能指导实践的结论。
